## The one-line idea

**You talk to ONE mind (Nemotron). The other Crusoe models are slots inside its head.
You use the one mind to see how the other models would interact with your system —
and its single photoreal face morphs with which slots are loaded and who is talking.**

## Hard requirements (locked with the owner)

1. **One thing you talk to.** A single entity — Nemotron Super-120B. **No model picker, ever.**
2. **Slots = its cognition.** Each slot is a different Crusoe model (DeepSeek, Llama, Qwen,
   Gemma, GPT-OSS, …). They are organs of one mind, not separate chatbots.
3. **See the slots think.** As the mind answers, you can see *how each slotted model would
   interact with your message* — their perspectives surface inside the one mind.
4. **One photoreal face that morphs.** Generated by Perfect Corp (text-to-image), ONE shared
   photoreal style so it can actually morph. The face changes based on (a) which slots are
   loaded and (b) who is currently talking. **No static cartoon JPGs.**
5. **The Arena is the front-end for Crusoe.** The product is the single experience over
   Crusoe's whole catalog — never a menu of models.
6. **Boundary + retry = the nervous system.** Gatekeeper in/out (FAIL CLOSED), self-healing,
   and — done for real — routed through the **TrueFoundry AI Gateway** for genuine
   retry/fallback/health-cooldown. Not faked `random.choice` chaos.
7. **Beauty is the face.** Perfect Corp generates AND can grade the mind's emergent face.
   Not a separate tab.

## Modes (amendment — 2026-05-29)

The single entity is the **default**. There is a second mode; both run on the *same* `Mind`
engine — Mode 2 is an orchestration loop over it, not a new product.

- **Mode 1 — Converse (default).** You ↔ ONE mind (Nemotron), slots inside it. This is
  hard-requirement #1 and stays the front door. No model picker.
- **Mode 2 — Dialogue.** You summon **two minds**, each with a **different slot loadout**, and
  watch them talk *to each other*. You compose each mind by its slots (never by picking a model
  to chat with), then spectate. Two morphing photoreal faces in conversation.

Why Mode 2 earns its place (it is the *proof*, not drift): the single-mind concept's biggest
risk is "felt coherence" — a skeptic seeing one mind may read it as "queried some models and
summarized." Two minds with different slots **visibly diverging** in a live dialogue is the
demonstration that *slots = cognition*, and it cannot be mistaken for a model menu. It is
additive: a `Mind.respond()` looped against a second `Mind`. Build it **after** Mode 1 works.

## Architecture

```
You ─▶ [Boundary gatekeeper IN — fail closed]
            │
        THE MIND  (Nemotron Super-120B — one voice, one face)
            │  fans your message to its slots
   ┌────────┬────────┬────────┬────────┐
 DeepSeek  Llama   Qwen    Gemma   GPT-OSS     ← slots = real Crusoe calls
   └────────┴────────┴────────┴────────┘
            │  each slot returns "how I'd interact with this"
        Nemotron SYNTHESIZES one reply, aware of its slots
            │
   [Boundary gatekeeper OUT — fail closed] ─▶ one voice + visible slot perspectives
            │
   Face-state (active slots + current speaker) ─▶ morphing photoreal portrait
```

Calls route through the **TrueFoundry gateway** (Crusoe registered as an OpenAI-compatible
provider) so retry/fallback/cooldown are real.

## Engine design (`src/colosseum/mind.py`) — start here

- `Slot(model_id, label, lens)` — a model in the head + a one-line "lens" (how it tends to think).
- `SlotPerspective(model_id, label, content)` — what one slot would do with the message.
- `MindTurn(user_message, reply, perspectives, speaker, gatekeeper_log, blocked)`.
- `Mind(main_model=Nemotron, slots, client)`:
  - `respond(message, history) -> MindTurn`:
    1. gatekeeper IN (**fail closed**: empty/unparseable ⇒ BLOCK).
    2. each active slot returns a short perspective (real Crusoe call to that model).
    3. main model synthesizes ONE reply, given the message + all slot perspectives
       (`max_tokens` high enough to survive Nemotron reasoning-token starvation; retry on empty).
    4. gatekeeper OUT (**fail closed**).
  - `face_key(speaker)` — `(sorted active slot ids, speaker)`; drives which portrait to show.
  - `face_prompt(speaker)` — one photoreal-portrait prompt blending the active slots'
    personalities, weighted toward the current speaker. (Generation lands in P3.)

### Engine invariants
- Gatekeeper is **fail closed** everywhere (no SAFE/allow default on empty output).
- Slots are **real** model calls — no model roleplays another.
- Synthesis never silently returns empty; it retries, then surfaces an honest state.
- The engine exposes face-state but does not itself block on image generation.
